# aml task assist

本机打开 `/widget/`，通过右上角「系统配置」设置 AML 服务地址、业务 Token、调度专用 Token 和模型参数；通过「定时扫描」页面设置扫描开关、周期和每轮提交上限。

页面配置保存在 MySQL，优先于环境变量；凭证不回显，留空保留，勾选清除后删除。AML 地址用于后续业务请求，模型参数用于后续模型调用；调度配置约 5 秒内生效。关闭扫描并保存后，不再启动新一轮，当前轮次会在后续分页或提交前检查开关并停止，已发出的请求会完成。扫描间隔为 60～604800 秒，每轮提交上限为 1～100 条，手动扫描也使用此上限。设置接口仅限本机同源访问。

首次读取配置时会检查并补齐旧配置表缺少的业务字段。运行账号只有 DML 权限的部署，需要先由 DDL 账号在目标数据库执行 [业务配置迁移](sql/V0.8.0__add_business_settings.sql)。新数据库使用 [初始化脚本](sql/mysql8-init.sql)。未保存的新字段沿用环境变量默认值。配置读取失败时弹窗仍会打开，显示错误并支持重试。

模型观测只记录发送对话的接口（同步问答、流式问答及兼容查询入口）。心跳、配置、待办、会话历史和 Trace 查询不生成链路；旧的非对话记录不进入列表或看板。模型调用记录实际输入消息、提供方返回的思考或推理摘要、输出、工具选择与参数、可选工具约束、调用耗时、首个模型分片耗时、Token 用量及提供方返回的缓存和推理用量。模型未返回思考或用量时页面会明确标注，不推测或补造。超出 `TRACE_MAX_PAYLOAD_CHARS` 的内容会截断，凭证继续遮盖。

聊天窗口实时展示思考和工具执行，历史回复可查看已保存的思考记录。「查看全链路」显示单轮模型与工具时间线；「看板」可按当前会话汇总多轮耗时与 Token，并点击任意轮次查看模型输入输出。流中断后不会自动重发问题。

会话使用首次提问作为名称，过长时截短显示，历史默认标题也会从首条问题显示名称。左侧历史栏可收起；顶部「我的待办」显示待办总数，点击打开右侧任务抽屉。抽屉按分类显示数量并支持折叠，风险和受益所有人列表支持加载更多，可加宽抽屉查看多列任务。

规则的源码路径和行号保留在内部规则映射中供维护者追溯，不再作为工具返回的 `source` 提供给模型。模型仍可使用规则说明和实时业务查询结果，材料的 `source_id` 与原件引用不受影响。
