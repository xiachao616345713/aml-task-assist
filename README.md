# aml task assist

主要用于嵌入 AML 业务系统：**选择任务类型，上传整批资料，自动匹配审批记录、整理并提交确定项**，无需逐条选择待办。不确定、冲突和缺件的对象跳过。目标记录、完整实际payload、结果与资料来源保存在批次台账及本次对话，AML可按业务记录反查。详见[批量处理与嵌入契约](DESIGN.md)。

顶部「上传资料」为批量入口，「我的待办」只用于查看和筛选。支持 PDF、DOCX、XLSX、TXT、CSV、JSON、Markdown、ZIP。当前依照要求使用现有推进流程接口；后续通过 `AML_BATCH_WRITE_PATHS` 替换为 AML 仅保存接口，payload不变。风险单客户任务和核验初审确认无差异已接入，其他业务分支不能确定完整参数时跳过。

更新后重启 Python 服务并刷新页面。已有数据库使用 [批量资料迁移](sql/V0.9.0__material_batches.sql)；有DDL权限时批量接口首次访问也会补建新表，无权限会提示迁移。测试用[37份混乱材料](samples/materials/README.md)可用于解析和跳过场景，不会凭虚构编号命中真实待办。

本机打开 `/widget/`，通过右上角「系统配置」设置 AML 服务地址、业务 Token、调度专用 Token 和模型参数；通过「定时扫描」页面设置扫描开关、周期和每轮提交上限。

页面配置保存在 MySQL，优先于环境变量；凭证不回显，留空保留，勾选清除后删除。AML 地址用于后续业务请求，模型参数用于后续模型调用；调度配置约 5 秒内生效。关闭扫描并保存后，不再启动新一轮，当前轮次会在后续分页或提交前检查开关并停止，已发出的请求会完成。扫描间隔为 60～604800 秒，每轮提交上限为 1～100 条，手动扫描也使用此上限。设置接口仅限本机同源访问。

首次读取配置时会检查并补齐旧配置表缺少的业务字段。运行账号只有 DML 权限的部署，需要先由 DDL 账号在目标数据库执行 [业务配置迁移](sql/V0.8.0__add_business_settings.sql)。新数据库使用 [初始化脚本](sql/mysql8-init.sql)。未保存的新字段沿用环境变量默认值。配置读取失败时弹窗仍会打开，显示错误并支持重试。

顶部「资料提交记录」是独立历史入口，可按任务类型、批次状态筛选并翻页，查看来源数、提交成功/跳过/结果不明数量、逐项实际payload和接口结果；记录可跳转对应对话、本条处理Trace及整批Trace。

模型观测记录发送对话的接口，以及批量资料的创建、上传、识别匹配和提交。心跳、配置、待办、会话历史和 Trace 查询不生成链路；批量创建、上传和处理分别有独立Trace，通过批次ID关联；会话、资料提交记录和完整链路可相互跳转。模型调用记录实际输入消息、提供方返回的思考或推理摘要、输出、工具选择与参数、可选工具约束、调用耗时、首个模型分片耗时、Token 用量及提供方返回的缓存和推理用量。模型未返回思考或用量时页面会明确标注，不推测或补造。批量链路明确标记用户选择的任务类型、编排器调度的业务工具、模型结构化识别结果和原文引用校验，时间线同时展示业务HTTP参数、结果及每段耗时。超出 `TRACE_MAX_PAYLOAD_CHARS` 的内容会截断，凭证继续遮盖。

聊天窗口实时展示思考和工具执行，历史回复可查看已保存的思考记录。「查看全链路」显示单轮模型与工具时间线；「看板」可按当前会话汇总多轮耗时与 Token，并点击任意轮次查看模型输入输出。流中断后不会自动重发问题。

会话使用首次提问作为名称，过长时截短显示，历史默认标题也会从首条问题显示名称。左侧历史栏可收起；顶部「我的待办」显示待办总数，点击打开右侧任务抽屉。抽屉按分类显示数量并支持折叠，风险和受益所有人列表支持加载更多，可加宽抽屉查看多列任务。

业务规则只保留流程标识、办理边界和接口契约，不保存宿主源码或目录引用。模型仍可使用规则说明和实时业务查询结果，材料的 `source_id` 与原件引用不受影响。

批量Trace关联表迁移：[sql/V0.9.1__batch_traces.sql](sql/V0.9.1__batch_traces.sql)。有DDL权限时首次访问会补建；DML账号需先执行迁移。旧批次无法补造历史模型调用和Token。Trace默认保留30天，提交台账和原件独立持久保存。
